# Phase 1: Web Scraping & Alternative Data Ingestion Architecture

This document details the architectural decisions, security models, entity linkage frameworks, and execution roadmap for the **Market Marksman / Predictive Opportunity Intelligence Platform**.

---

## 1. Security & GCP Secret Manager Migration

### Problem Identified
Storing sensitive API keys, vendor tokens, or client credentials in browser `localStorage` introduces significant client-side exposure risks, XSS vulnerabilities, and unauthorized access vectors.

### Implemented Solution & Production Architecture
1. **Server-Side Key Resolution (`process.env`)**:
   - All third-party credentials (Gemini API key, SAM.gov tokens, openFDA keys, custom web scraper authorization headers) are stored strictly server-side.
   - Client applications never access raw keys. All external data fetching and AI synthesis requests pass through secure server-side proxy endpoints (`/api/gemini`, `/api/scrape/web`, `/api/linkedin/scrape`).

2. **GCP Secret Manager Integration Blueprint**:
   - In production deployments on **Google Cloud Run**, secrets are injected dynamically at runtime via GCP Secret Manager volume mounts or environment variable references:
     ```bash
     gcloud run deploy market-marksman-api \
       --image gcr.io/PROJECT_ID/market-marksman:latest \
       --set-secrets GEMINI_API_KEY=projects/PROJECT_ID/secrets/gemini-api-key:latest \
       --set-secrets SCRAPER_BEARER_TOKEN=projects/PROJECT_ID/secrets/scraper-token:latest \
       --region us-central1
     ```
   - **Zero Client-Side Leakage**: The browser frontend interacts purely with authenticated session tokens and REST/JSON endpoints.

## 2. Early Entity Linkage & Canonical Entity Resolution

### Why Early Resolution Matters
Unstructured alternative data signals (e.g. scraped Reddit threads, RSS press releases, LinkedIn job surges, USPTO patent claims) often reference company names inconsistently (e.g., *"Anduril"*, *"Anduril Defense"*, *"Anduril Corp"*). De-risking entity resolution early prevents signal fragmentation and enables accurate aggregation.

### The Canonical Entity Linkage Engine (`/api/entities/resolve`)
Our backend implements a three-stage probabilistic entity resolution pipeline:

1. **Exact Alias Matching (Confidence ~0.98)**:
   - Scans incoming raw text against a predefined canonical entity dictionary (`CANONICAL_ENTITIES`).
   - Maps aliases directly to canonical names, unique IDs, and financial identifiers (e.g., `NYSE: PLTR / CIK 0001321655` or `PRIVATE (Series E)`).

2. **Fuzzy Token Matching (Confidence ~0.85)**:
   - Tokenizes entity names into distinct root morphemes (>3 characters).
   - Identifies partial name matches across unstructured scraped descriptions.

3. **Sector Context Inference (Confidence ~0.68 Fallback)**:
   - When no specific entity name is matched, infers entity groupings based on target industry keywords (e.g., *Clean Energy & Fusion*, *Defense & Aerospace*, *Semiconductors & Nanotech*).

#### Sample Resolution Response Structure:
```json
{
  "canonicalEntity": "Anduril Industries",
  "entityId": "ENT-ANDURIL-01",
  "tickerOrCik": "PRIVATE (Series E)",
  "confidenceScore": 0.98,
  "matchType": "Exact Alias",
  "matchedAlias": "Anduril Defense"
}
```

## 4. Accelerated Architecture & Cost Optimization

### Speed & Efficiency Decisions
1. **Serverless Cloud Run over Kubernetes/Ray Clusters**:
   - Replaces heavy, expensive Kubernetes/Ray cluster infrastructure with containerized **Google Cloud Run** backend instances.
   - Benefits: Scales to zero when idle ($0/month dev overhead), sub-second cold starts, and handles up to 80 concurrent requests per container instance.

2. **Decoupled REST API + Web Workers**:
   - Long-running web scraping operations run asynchronously on the server and stream progress logs back to the UI via REST polling or Server-Sent Events (SSE).

3. **Open-Source Tooling Stack**:
   - **PostgreSQL / dbt / Airflow**: For structured data warehousing and ingestion scheduling.
   - **Hugging Face / spaCy**: For lightweight, domain-tuned NLP Named Entity Recognition (NER).
   - **SHAP / LIME**: For model interpretability and plain-English broker explanations.
